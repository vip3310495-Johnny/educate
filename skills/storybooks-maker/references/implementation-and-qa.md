# 實作、驗收與交付

## 先讀最新作品

既有作品先找到並讀取目前的檔案／原始碼。依提供的檔名、既有檔案身分與網站專案定位；沒有明確對應時搜尋，不能猜識別碼。只改需求範圍內的內容，保留未提及的使用者修改。

若是 Sites 管理的網站，讀取當前 Sites 流程，使用正式來源取得與發布工具；不要把本機舊副本當成最新來源。保留目前分享權限。私人網站的登入畫面不表示發布失敗，也不允許繞過授權。

## 靜態架構

優先採簡單可維護的 HTML／CSS／JavaScript。可以模組化開發，再打包成單一 HTML。不要為純靜態繪本加入無必要的伺服器或登入系統。

建議拆分故事資料、場景互動、音訊、主控制器、樣式與資產；例如 `story-data.js`、`scene-engine.js`、`audio.js`、`app.js`、`styles.css` 與 `assets/`。路徑及檔名依專案調整。

故事資料至少分開 `title`、正文陣列、插畫 alt、共讀提示與互動規格。正文是朗讀唯一來源；介面字串不能混進正文。

主控制器統一管理頁碼、上一頁／下一頁、目錄、朗讀、音量偏好與重設。處理首末頁邊界、鍵盤方向鍵與 Home／End，觸控翻頁需防止與舞台點按衝突。避免翻頁後還播放前頁聲音。

使用圖片資產映射集中解析路徑，使網站版和離線版共用同一套資料與互動引擎。建置工具替換資產映射時，保留 MIME 類型與正確編碼；不要用會破壞 JavaScript 字串的全域替換。

## 離線打包

單檔交付包含所有 CSS、程式、圖像、BGM、音效與字型，通常以 data URI 內嵌。影片或較大檔案只有使用者接受多檔交付時才拆出。

檢查 HTML 的 `src`／資源 `href`、CSS `url(...)`／`@import`、字型來源與 JavaScript 中動態載入的路徑；沒有遠端 `<script>` 不等於已離線。署名連結可保留外部網址，但不得成為閱讀必要依賴。

字型使用授權允許的子集、圖片合理壓縮、配樂選適當長度與編碼。記錄最終檔案大小，避免無必要地內嵌原始超大圖片；不要為減小檔案而犧牲可讀性或刪掉使用者要求的音樂。

以離線狀態實際打開最終 HTML，驗證各頁圖片、所有互動入口、音樂與字型。系統 TTS 可用性另外標記；不要把裝置未提供的語音算成內嵌能力。

## 按風險選擇驗證

新書完成時做完整逐頁檢查；後續修改測影響範圍與必要回歸。語音文字的小修改應驗證實際傳入 TTS 的內容與換頁取消，不必重做所有美術資產或添加只複製程式邏輯的測試。

### 交付前的兩項固定檢查

1. **可移動物件裁切檢查：**列出每頁會移動、縮放、旋轉或變形的角色與道具；先檢查透明素材的 alpha 邊界、頭髮、四肢、尾巴、翅膀、配件及陰影是否完整，再在桌面與手機逐一觀察起始、中途、結束、重播。檢查圖集切格、圖片尺寸、transform-origin、overflow／clip-path／mask 及前景遮擋，必要時加查旋轉或縮放幅度最大的時點。正常走出畫面或進入前景後方可保留；不得把意外缺角、硬切邊或頭腳被截斷當作離場效果。記錄頁次／物件、發現問題、修正及複驗結果。
2. **跨頁故事連續性檢查：**按閱讀順序連讀全部最終正文，先確認開頭已交代主角的必要背景、人物關係、生活處境與事件起因，再逐一對照「本頁結尾 → 次頁開頭」。對照實際查閱的原作／影視版本與核准的改編取捨，檢查事件因果、角色動機與已知資訊、時間經過、場景轉換、人物去向及關鍵道具／變身狀態；重要情報或角色若突然出現，補足前置交代，修正版本混接造成的矛盾。刪除重複贅述並補入過渡句時，同步更新朗讀來源、互動後敘述與分鏡資料，再重新檢查受影響的前後頁。記錄每個頁間銜接及補寫結果，不能只各自校對單頁。

|---|---|

| 原作參考與角色背景 | 有原作／影視參考時已實際查閱並記錄版本、來源與改編取捨；開頭清楚交代主角必要背景，未把未經來源支持的身世冒充原設定 |
| 跨頁故事連續性 | 分鏡交付前及最終正文均已全篇連讀；每一組相鄰頁的因果、時間、位置、動機、已知資訊與物件狀態能接續，必要過渡已補入正文及朗讀來源，重複贅述與版本矛盾已修正 |

| 圖外敘事與文字避讓 | 通用點按口號已移除；原文字框敘述在插畫下方清楚可讀，初始及互動後內容符合情節；圖片內無遮擋人物／動作的彈框或懸停／焦點標籤，互動點與無障礙名稱保留 |
| 動態與手機驗收 | 記錄動畫開始、中途、結束、重玩與換頁後的狀態；在窄手機實際操作，檢查文字遮擋、觸控位置及閱讀順序，不只看靜態截圖 |

| 資產與程式 | 無破圖、遺失檔案、應用本身的錯誤；基本語法檢查通過 |
| 授權與離線 | 音樂／字型來源及必要署名齊全，最終 HTML 離線可讀可玩 |

驗證 UI 使用當前環境支援的瀏覽器工具／技能，不寫死控制方式或私有 API。需要聲音確認時區分：播放器解碼與狀態、音效時間線、實際聽測。瀏覽器沒有可用 TTS 時，驗證正常降級並說明朗讀未在該環境聽測。

## 保存與部署

遵循環境的持久保存方式。可下載 HTML 存為正式檔案；既有檔案盡量替換同一身分，使用當下版本保護避免覆蓋較新內容。外部 Git 管理的網站來源依其流程保存，不額外複製整個原始碼專案到檔案空間。

### 完成後預設上傳 Google 雲端硬碟

故事書完成或既有書籍完成修訂時，自動執行上傳，無須再次詢問是否要放到雲端硬碟；使用者明確要求不上傳、只保留本機或指定其他目的地時，以該次指示為準。僅交付規劃／分鏡預覽時，不把尚未完成的互動書當成成品上傳。

1. 準備與本次交付版本一致的單一離線 HTML、含原始碼／全部資產／音樂／必要授權的 ZIP，以及最新故事腳本與分鏡。保留既有實測限制，不把成功上傳等同所有驗收通過。
2. 優先使用當下 Google Drive 工具與流程。先查找已指定或已存在的該書資料夾；新書沒有對應資料夾時，依使用者既有整理方式建立以書名命名的資料夾。只有確實無法從既有資料判定目的地時才詢問，不猜資料夾 ID。
3. 新書上傳新檔；修訂既有書籍時替換已核實的同一檔案內容，保留檔案 ID、網址、資料夾及分享權限，避免每次產生重複副本。HTML 與 ZIP 維持原始檔案格式，不轉成 Google 文件。
4. 等待每個上傳／替換動作完成，再讀取雲端檔案中繼資料或資料夾內容，核對檔名、類型、大小與目的地；能取得雜湊時比對本機檔案。記錄實際回傳的檔案／資料夾連結。
5. 最後提供 Google Drive 資料夾或成品連結，簡短說明已保存的內容。上傳失敗時保留可下載成品，明確標示尚未上傳成功；不要因資料夾已建立或部分檔案成功便宣稱全部完成。

上傳雲端硬碟是保存副本，不代表同意公開分享或發布網站；維持既有存取設定，也仍須遵守環境的持久保存規則。不要將帳號、權杖或本次專案的私人識別碼寫入可共用技能。

只有網站／部署在請求範圍時才發布。用 Sites 或使用者指定的平台；已有網站沿用專案、網址與存取設定。核對發布包與實際驗收版本一致，等服務回報完成，再給網址。

最後用簡短文字說明完成項目，提供網站與／或離線檔的真實連結。不要把登入權杖、內部檔案識別碼或私有旁路連結寫進作品。保留必要署名與素材許可說明，不把內部製作細節塞進孩子的主要閱讀流程。
